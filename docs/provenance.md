# 旧版からの変更と資料の整理

## 確認した元資料

大学講義「プロジェクト演習12」のフォルダを対象に、120ファイルを棚卸ししました。最終提出のJava 16クラス、途中版、5つのZIP内の構成、CSV、設計図、提出レポートと週次報告を照合しています。配布教材・練習課題・生成済みclass・空のSpring Bootひな形は、本アプリの実装とは区別しました。

最終版の基準は`最終課題/java/project`です。レポートのクラス図、ユースケース、SQL、担当記述をコードと対応させています。元フォルダは変更していません。このリポジトリには個人情報を含む原本や講義資料を転載していません。

## 授業当時の成果

4人で、店舗選択、複数アレルゲンの除外、予算・カロリーによる検索、価格・カロリー・販売数による表示、店舗限定商品の表示、注文、在庫管理、売上確認を統合しました。

担当者本人の最終レポートでは、アプリケーション設計、`Main`・`CalorieFilter`・`PriceFilter`・`LimitedMenu`、全クラス統合、表示改善が担当範囲として記録されています。チーム制作後の個人拡張として、管理者の継続操作、`AddMenu`・`AddSupply`が追加されています。

## 保守版での対応

| 旧版で確認した課題 | 今回の対応 | 検証 |
| --- | --- | --- |
| 絞り込み表示の存在確認で`next()`を呼び、その後のループで先頭行を飛ばす | 結果を一度だけ走査してリスト化 | 1件のみ・先頭行の回帰テスト |
| 除外指定0件でも`IN (...)`を生成 | 除外がない場合はそのSQL条件を付けない | 条件なし・複数除外・不存在ID |
| 複数のScannerでSystem.inを共有 | 入力口を1つに統一、EOF・不正数値を処理 | 注文完了・再入力・途中終了 |
| 接続設定が複数クラスへ直書き、root・空パスワード | 接続設定を集約、環境変数とTLS検査 | 不足設定・不正ホスト・root拒否 |
| 固定値の管理パスワード | ソルト付きハッシュ・非表示入力・3回制限 | ハッシュの正常・不正・欠落 |
| 在庫をSELECTしてから無条件UPDATE | 行ロックと条件付き減算、注文全体のトランザクション | 20件同時注文・途中のSQL失敗 |
| 在庫更新が他の注文を上書きする | バージョンを用いた競合検査 | 古い画面・ABAケース |
| 売上が現在価格×注文数のみ | 注文時の価格と明細を保存して集計 | 価格変更後・店舗分離・大きな合計 |
| `MAX(ID)+1`採番と複数テーブルの別々の確定 | 自動採番、メニューと関連情報の一括確定 | 登録途中のSQL失敗・不正参照 |
| ビルド・DB作成手順が分散 | Maven Wrapper、schema、架空seed、CI | H2とMySQLで同じテスト |

既存CSVは実在の店舗・商品を含み、アレルゲン情報の正確性や再利用条件を保証できないため、公開版は新しく作った架空データに置き換えました。

旧版の`orderCount`には注文時刻・単価履歴がないため、過去の注文明細へ正確に復元できません。保守版は新規スキーマを使い、旧DBのデータを勝手に変換・移行しません。配布教材由来の抽象クラスやサンプルも転載せず、保守版として構成を再実装しています。
